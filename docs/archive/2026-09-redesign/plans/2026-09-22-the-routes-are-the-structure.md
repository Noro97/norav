# The Routes Are The Structure — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every navigation destination a resolvable address of its own — four menu items, four real routes, no fragments — and remove the seven navigation defects the audit found.

**Architecture:** Migration 0028 rewrites the navigation collection to four items, keeps `work` and `contact` as real pages and fills them, soft-deletes the three pages whose content folds elsewhere, and renames three case-study slugs. Two small code changes follow the content: `resolveTarget` loses the `SITE_SLUG` special-case that rendered the phantom Contact item, and `Navigation.handleClick` stops writing fragments into the address as it scrolls. `vercel.json` gains the redirects. Nothing about the router's design changes — slugs still come from the CMS and addresses are still derived.

**Tech Stack:** Vite 6 · React 19 · TypeScript 5.9 · react-router 7 · Tailwind 4 · vitest + jsdom · PostgreSQL migrations tested on PGlite.

**Spec:** `docs/superpowers/specs/2026-09-22-site-redesign-design.md` — sections *URLs and navigation* (the governing rule, amended 2026-09-22), *Pages*, *Migrations → 0028*, and the `Navigation.tsx` / `src/content/navigation.ts` entries under *Code — Added or changed*.

- [ ] **Step 1: Write the migration**

```sql
-- =============================================================================
-- norav CMS · 0028 · The routes are the structure
--
-- The menu had eight items and three of them did not name an address. Contact
-- pointed at `site` — the page that is not a page, whose blocks render below
-- every other one — so the site rendered it as a bare `#terminal` on whatever
-- page you happened to be on: nothing to link, nothing to send, nothing for a
-- crawler to find. Overview and Projects both landed on `/work`, two items for
-- one destination. And `/experience#experience` and `/automation#workflows`
-- each named the only section on their page, so the fragment said nothing the
-- route had not said already.
--
-- So the menu becomes four items and each one is a route: Work, About,
-- Writing, Contact. `work` and `contact` stay real pages — `/work/logistics`
-- existed while `/work` was about to 301 away, and a path whose parent does
-- not resolve is the thing this redesign is for. Experience, Skills and
-- Automation go, their content folded into home and About by 0029 and 0030.
--
-- Pages are soft-deleted rather than dropped: the copy stays in the database
-- and un-hiding one is a single update.
-- =============================================================================

-- 1 ---------------------------------------------------------------------------
-- The three case studies get their product names. A slug is the address, and
-- `logistics` describes a category while `nexusroute` names the thing.
--
-- `pages.slug` is plainly unique, so a rename onto a slug that already exists
-- would fail rather than merge. Guarded so a replay is a no-op.

update pages set slug = 'work/nexusroute'
 where slug = 'work/logistics'
   and not exists (select 1 from pages taken where taken.slug = 'work/nexusroute');
update pages set slug = 'work/filtergraph'
 where slug = 'work/ecommerce'
   and not exists (select 1 from pages taken where taken.slug = 'work/filtergraph');
update pages set slug = 'work/merchforge'
 where slug = 'work/merch'
   and not exists (select 1 from pages taken where taken.slug = 'work/merchforge');

-- 2 ---------------------------------------------------------------------------
-- The pages whose content moves elsewhere. A page is retired by its status —
-- `pages` has no `deleted_at`, and `archived` is what publish already skips.
-- Their blocks are soft-deleted too: the publish step walks blocks by page id,
-- and leaving live rows under an archived page is a trap for whoever un-files
-- it later.

update blocks
   set deleted_at = now()
  from pages page
 where page.id = blocks.page_id
   and page.slug in ('experience', 'skills', 'automation', 'test')
   and blocks.deleted_at is null;

update pages set status = 'archived'
 where slug in ('experience', 'skills', 'automation', 'test')
   and status <> 'archived';

-- 3 ---------------------------------------------------------------------------
-- `/work` becomes the index of the five studies rather than a redirect, and
-- `/contact` keeps the CTA it was given in 0023. `work` exists from 0012 and
-- `contact` from 0023; this only makes sure both are present and published,
-- so the file is safe to replay and safe on a database that has one but not
-- the other.

insert into pages (slug, status, seo)
values ('work', 'published', '{}'::jsonb),
       ('contact', 'published', '{}'::jsonb)
on conflict (slug) do nothing;

update pages set status = 'published'
 where slug in ('work', 'contact') and status <> 'published';

-- 4 ---------------------------------------------------------------------------
-- The terminal goes back to `site`, where the chrome lives, so it renders below
-- every page as an easter egg behind the footer's toggle rather than being the
-- contact route. 0023 had moved it onto `contact`; that was when `contact` was
-- the only place to reach him.
--
-- `blocks_anchor_key` is unique per (page_id, anchor_id) among live rows, so a
-- move onto a page that already holds a `terminal` anchor would fail. `site`
-- holds the footer and nothing anchored `terminal`, but the guard costs a line.

update blocks
   set page_id = (select id from pages where slug = 'site')
 where type = 'terminal_footer'
   and deleted_at is null
   and page_id <> (select id from pages where slug = 'site')
   and not exists (
     select 1 from blocks living
      where living.page_id = (select id from pages where slug = 'site')
        and living.anchor_id is not distinct from blocks.anchor_id
        and living.deleted_at is null
        and living.id <> blocks.id
   );

-- 5 ---------------------------------------------------------------------------
-- The menu. Four items, four routes, no anchors. Everything else in the
-- collection goes: an item naming a page that no longer exists would be
-- dropped at render anyway, and leaving it in the admin invites someone to
-- wonder why it does nothing.
--
-- `about`, `writing` and `contact` already exist from 0013 and 0020, with the
-- labels this menu wants, so they are repointed rather than replaced and keep
-- their ids and their translations. Only `work` is new — `overview` and
-- `projects` both pointed at that page, and neither name says what it holds.

update entries set deleted_at = now()
 where collection = 'navigation'
   and deleted_at is null
   and slug not in ('work', 'about', 'writing', 'contact');

insert into entries (collection, slug, position, is_visible, data)
values ('navigation', 'work', 1000, true, '{"page":"work","anchor":"","external":""}'::jsonb)
on conflict (collection, slug) where deleted_at is null do nothing;

insert into entry_translations (entry_id, locale, data)
select entry.id, seeded.locale, seeded.label::jsonb
  from entries entry
  join (values
    ('en', '{"label":"Work"}'),
    ('ru', '{"label":"Работы"}')
  ) as seeded(locale, label) on true
 where entry.collection = 'navigation'
   and entry.slug = 'work'
   and entry.deleted_at is null
on conflict (entry_id, locale) do nothing;

-- The three that survive point at their own page and at no section. `contact`
-- is the one that moves: 0013 aimed it at the chrome page and 0023 at the
-- terminal on `contact`, and neither is an address a reader can be sent.
update entries
   set data = data || jsonb_build_object('page', slug, 'anchor', '', 'external', ''),
       position = case slug
                    when 'work' then 1000 when 'about' then 2000
                    when 'writing' then 3000 else 4000
                  end,
       is_visible = (slug <> 'writing')
 where collection = 'navigation'
   and deleted_at is null
   and slug in ('work', 'about', 'writing', 'contact');
```

Three details verified against the schema, do not "fix" them: `entry_translations`'s payload column is **`data`**, not `content` (`db/migrations/0004_collections.sql:26-33`); its primary key is `(entry_id, locale)`, which is the conflict target; and `entries` has a *partial* unique index, so its conflict target must carry the predicate — `on conflict (collection, slug) where deleted_at is null`. `status` is left at its default, exactly as 0013 and 0020 do for navigation labels.
